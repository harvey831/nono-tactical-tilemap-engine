## 1. 核心幾何架構：分層的正確定義 (The True Layered Map Pipeline)

> [!IMPORTANT]
> **【徹底告別舊模型】**：
> 嚴禁將「分層」理解為「幾張平面 PNG 疊加、用 CSS/Offset 往上硬推、加透明度開關」！那只是平面貼圖遮罩，無法形成真實的戰術高差、掩體與立面遮擋。

分層地圖的唯一正確定義：**「真高程柱體拓撲投影 (2.5D Column & Run Topological Projection)」**。

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ 🌟 真分層五部曲核心流向 (True Elevation Pipeline SSOT)                      │
│                                                                             │
│ 1. 每格高度資料 (Cell Heightfield)                                          │
│    • 每個網格 (x, y) 擁有整數高度 H（如 H-2 ~ H6）。                        │
│    • 高度矩陣是幾何生成的唯一真相源。                                       │
│                                                                             │
│ 2. 頂面按高度投影 (Top-Face Vertex Projection)                              │
│    • 投影作用在【頂點 (Vertices)】，絕對不是作用在整張圖！                   │
│    • 基準投影位移：ΔY = 0.72 格 / 級（向上抬升）、ΔX = 0.12 格 / 級（隨鏡頭  │
│      側向角度連續平滑微移）。                                                │
│                                                                             │
│ 3. 面與面之間貼側壁 run (Vertical Wall Runs)                                 │
│    • 每格是從自己高度落到鄰格高度的柱子；立面歸較高格繪製。                 │
│    • 側面是「一段一段的豎向 run」：貼圖採用正面 tile 沿高度向 BOX 壓縮       │
│      （每級一片，片與片之間不插值，寬度不動），絕非把 tile 暴力擠扁。        │
│                                                                             │
│ 4. 建築是牆環＋門窗＋樓板＋屋頂的柱子 (Buildings as Column Assemblies)       │
│    • 建築不是死板圖形，而是由室內樓板、牆體環、門窗立面、頂部壓頂 (cap)     │
│      組裝的複合幾何體。父層在洞口處挖空透出下層。                           │
│                                                                             │
│ 5. 剖面只是換畫法，不是換一張圖 (Sections as Rendering Modes)               │
│    • 剖面視圖（Cutaway View）是在同一個三維幾何模型上，依高度門檻決定        │
│      何者繪製頂面、何者切開顯示剖面柱芯與室內，絕非另畫一張獨立假圖！       │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 2. 核心幾何與光柵化規則摘要 (Core Elevation Rules: R0–R49 Summary)

必須嚴格遵守以下由實戰教訓萃取的拓撲與光柵化規則：

| 規則代號 | 核心規則名稱 | 規則要點與幾何物理原理 |
|:---|:---|:---|
| **R0** | **先格後畫對齊律** | 環境道具與地景物件必須**先定義格再繪製**，物件的物理尺寸與著地位置嚴格對齊網格基準。 |
| **R7** | **先立面後頂面繪製序** | 每格渲染時，必須**先畫面（崖面／垂直牆面），再畫頂面**；整個地圖遍歷順序嚴格由北到南（row 0 → row N），確保近景與頂面正確覆蓋遠設立面。 |
| **R13 / R14** | **側壁豎向 run、BOX 壓縮與材質一致性** | 側面是「一段一段離散的豎向 run」；貼圖貼合方式為：**正面 tile 沿高度向進行 BOX 壓縮**（例如 32px 寬保持不變，高度縮至 23px；Python 使用 `Image.resize((32, 23), BOX)`，JS 使用 `drawImage` 並關閉 `imageSmoothingEnabled`）。**每級一片，片與片之間嚴禁插值**！絕對不要用 NEAREST，亦不可用 LANCZOS。**側牆 run 一律用該建築 style 的牆 tile**（石屋不能有木側壁，嚴禁風格材質撕裂）。 |
| **R15** | **柱體高差歸屬權** | 每格空間本質上都是**從自己高度落到相鄰格高度的立體柱子**。兩格之間的高差垂直面，統一**歸較高的格子負責繪製**落差立面。 |
| **R19** | **頂點級投影與光柵化取整** | 幾何投影計算作用於**四個頂點座標**，側面錯位隨鏡頭水平偏移 $x$ 保持連續浮點數變化；但在進行光柵化貼圖時才**執行座標取整**（Python `paste_parallelogram` 採整數 bbox，JS `drawPara` 前 `Math.round`）。**嚴禁在頂點幾何層提早取整**，否則相鄰板塊必出現撕裂縫隙！ |
| **R24** | **Row 內由遠至近排序** | 同一 row 之內的繪製順序，必須從**離鏡頭最遠的格子畫到最近的格子**（例如在鏡頭偏向時，依視角深度排序），確保坑底與低窪處能被前景河岸或高台正確遮蓋。 |
| **R25** | **樓梯建築腳印與梯洞規範** | 有樓梯的建築**腳印必須 $\ge 8\times 6$**。梯洞定義為整段梯級的格（2 格寬 × 整段長）；**豎井內牆一路落到樓板**，再蓋三階梯級；**不准拿地面 tile 填洞**。 |
| **R28 / R29** | **建築繪製序與單牆獨立裁切** | 建築渲染順序嚴格遵守：**室內 → 外牆 → cap (立面壓頂)**；每一道牆面各自進行背向與遮蔽可見性判定，確保視角切換時內側壁不會被錯誤透視穿透。 |
| **R30 / R31** | **雙格高實體門與甲板屋頂** | 門為兩格高物理空間，**必須獨立繪製一張完整兩格高的門立面資產**，嚴禁在單格門上敷衍加一條門楣；凡可走人的平屋頂，必須以 **deck（甲板／平台）** 語意結構定義與鋪設。 |
| **R32** | **門窗避讓與遮陽篷定位** | 遮陽篷為門廊機能組件，**必須覆蓋大門（門寬 + 左右各 1 格）**；嚴禁隨意放於窗下或無門牆面。 |
| **R33** | **招牌高度安全與貼牆投影** | 招牌不得撞窗撞門；先經 bbox 量高，計算必須滿足 $h + \text{高}/23 \le \text{牆高}$（超出牆頂即畫上屋頂破圖）；貼牆面的平行四邊形變換，鏡頭移動時必須與牆面完全同步。 |
| **R34** | **煙囪屋頂歸屬與 facade 欄位格式** | 煙囪屬於屋面結構，其 `kind` 必須為 `roof`（嚴禁當作牆面）；facade 的 `cell` 欄位必須為**整數 col**，嚴禁傳入 `[col, row]` 陣列。 |
| **R35** | **垂直過渡與光影倒角** | 水平頂面與垂直立面之間嚴禁生硬交界，必須具備過渡視覺要素：**崖緣過渡線、受光稜高光線、以及落地的接地陰影**。 |
| **R38** | **3/4 俯視手繪 2D 道具標準** | 地圖環境道具一律為一般 RPG tileset 的**手繪 3/4 視角 Sprite**（具備手繪透視、1px 暗色描邊與著地接觸陰影；**絕非**「頂面＋正面」投影盒，**嚴禁**將頂面壓扁成透視橢圓，亦不做真 3D 模型或 90 度正俯視）。大叔參考包（`Tilesets`）**只能參考視角、比例、色調，絕不直接貼進道具表**。 |
| **R39 / R40** | **負高度地景與邊界代畫** | 負高度（$H < 0$）必須具備明確的地景功能（如河道、水潭、排水分渠、木橋）；chunk 邊界外預設視為 $H = 0$，**邊界較低格必須代畫缺席鄰格所產生的面**，杜絕邊界露底。 |
| **R41** | **面材質隨頂面歸屬律** | 垂直立面的材質嚴格跟擁有它的頂面走。**水下的面一律用土岸材質**，嚴禁使用水色。 |
| **R42** | **一格寬水路溝渠規範** | 一格寬度水路採用 **H0 的溝 tile（16 向 autotile）** 實作，不做高差。 |
| **R43** | **全圖覆蓋驗證與輕量化交付** | 每次改動 `viewer.js` 都要在瀏覽器跑**全圖覆蓋掃描**才能發佈，瀏覽器強制 cache-bust；靜態圖用**像素掃描（背景色計數）驗 0 洞**；artifact 體積嚴格限制 **$\le 2\text{ MB}$**（內嵌圖 512px NEAREST + 128 色量化）。 |
| **R44** | **水體方塊與統一水面** | **一個水體只有一個水面；水面高度＝這個水體四周岸格的最低高度；四周不得有低於水面的格；河床必須低於水面。**（若本圖岸全是 H0，水面剛好是 0，畫在 0−0.15；若水池在 H2 台地且四周岸皆 H2 則水面為 2；若一格岸為 H1 則水面只能是 1）。水體旁邊不能有「低於水面又不是水」的泥灘（要泥灘就在岸高度貼泥地 tile）。 |
| **R45** | **水體半透明與分層渲染序** | 水體半透明（alpha 0.7）；繪製順序：**先畫河床 $\rightarrow$ 再畫水下岸壁（只在鄰格河床較高處）$\rightarrow$ 最後蓋水**。 |
| **R46** | **立面掛件與地面道具隔離** | facade 只放掛牆物（招牌、燈籠、遮陽篷）；麻袋、箱子等地面堆疊物件一律歸為 props，嚴禁塞入 facade。 |
| **R48** | **原生像素繪製與放大防鋸齒** | 道具繪製與參考圖並排放大 6× 對比，逐項對齊輪廓／色調／細節；必須**在原生像素（例 16×25）畫、描 1px 邊、再 2× NEAREST 放大**（在放大解析度直接畫再描邊會出鋸齒黑塊）。 |
| **R49** | **水體剖面語意與 surfaces 覆蓋** | 剖面語意：cut $\ge 0$ 看到水；cut $= -1$ 露河床（$-2$ 的床在 $-2$、畫 $-1\to -2$ 土岸壁）；cut $= -2$ 只剩 $-2$ 的床，**不能出現 $-1\to -2$ 的面**（岸壁頂端不高於 cut）。surfaces 必須覆蓋每個非建築格，含水格（水格 elevation 給水面 level，不是河床）。 |

## 3. 視覺透視與有機生活美學規範 (Aesthetic & Perspective Rules)

1. **100% 統一 3/4 斜上方俯視角 (Top-Down 3/4 Oblique)**：
   * **房屋**：俯視梯形斜面/平頂甲板 + 正面直立立面牆 + 雙格高閉合木門石階 + 右下立體投影陰影。
   * **樹木**：斜向立體樹冠 + 直立棕色樹幹 + 裸露根系 + 地表陰影（拒絕 90 度正俯視圓球！）。
   * **水井**：圓柱石砌井身 + 木拱架橫樑 + 絞盤滑輪 + 橢圓透視井口波光（拒絕平面圓圈！）。
   * **熔爐與桌椅**：石砌拱頂爐門與鐵砧、木桌面與垂直桌腿。
2. **立面與頂面黃金分割比例 (Golden Ratio Facade Proportions)**：
   * 建築正面立面牆保留充足舒展空間（約占總可視高 50%~60%），為正面木牆、雙格大門、窗台提供完整展示面，絕不可被屋頂過度壓迫。
3. **徹底拒絕幾何死板複製 (No Sterile Grid Copy-Paste)**：
   * 道路隨地勢蜿蜒起伏，帶有車轍暗紋與碎石；水渠伴隨梯田展開；建築依戰術節點錯落佈局，杜絕方塊複製。
4. **高密度 32×32 像素藝術防退化與 Autotile 禁令 (High-Density 32px Anti-Degradation Rule)**：
   * **【嚴禁 16×16 粗暴平塗降維】**：在 $32\times 32$ 像素網格下，每個單元均相當於高密度微縮畫布。**絕對禁止在程式碼中將格子暴力拆成 16×16 平塗色塊或死板 45 度幾何切角**，破壞精雕細琢的微風沙紋、石板 1px 倒角高光與勾縫！
5. **水體幾何與拓撲渲染管線 (Water Topology & Rendering Rules: R41, R42, R44, R45, R49)**：
   * **Minecraft 式水方塊與水面高度約束 (R44)**：一個水體只有一個水面；**水面高度＝這個水體四周岸格的最低高度；四周不得有低於水面的格；河床必須低於水面**。本圖岸全是 H0，所以水面剛好是 0（繪製於 $0 - 0.15$），那是結果而非規則；若水池挖在 H2 台地上、四周岸都是 H2，水面就是 2，河床為 1 或 0；若有一格岸只有 H1，水面就只能是 1（否則該岸格會被淹沒）。水體周邊嚴禁出現「低於水面又不是水」的泥灘坑洞；要泥灘就在岸高度鋪設泥地 (mud) tile。
   * **半透明水層與嚴格繪製序 (R45)**：水體採半透明渲染（alpha 0.7）。繪製順序：**先畫河床 $\rightarrow$ 再畫水下岸壁（只在鄰格河床較高處）$\rightarrow$ 最後覆蓋水面**。
   * **面材質隨頂面歸屬律 (R41)**：水下的垂直面一律使用土岸材質，嚴禁使用水色（面材質跟擁有它的頂面走）。
   * **水體剖面語意 (R49)**：$\text{cut} \ge 0$ 看到水；$\text{cut} = -1$ 裸露河床（$-2$ 的床維持在 $-2$、畫 $-1 \to -2$ 土岸壁）；$\text{cut} = -2$ 僅剩 $-2$ 的床，**不能出現 $-1 \to -2$ 的面**（岸壁頂端不得高於 cut）。
   * **一格寬水路溝渠 (R42)**：一格寬度的小水路採用 $H=0$ 的溝 tile（16 向 autotile）實作，不做柱體高差。
   * **Surfaces 全網格覆蓋 (R49)**：`surfaces` 必須 100% 覆蓋每一個非建築網格，包含水格在內（水格 elevation 給水面 level，絕非河床負高）。
6. **建築結構拓撲與立面掛件規範 (Building Assemblies & Facade Rules: R14, R25, R32, R33, R34, R46)**：
   * **樓梯腳印與梯洞規範 (R25)**：有樓梯的建築**腳印必須 $\ge 8\times 6$**。梯洞定義為整段梯級的網格（2 格寬 × 整段長）；**豎井內牆一路垂直落到樓板**，再蓋三階梯級；**嚴禁拿地面 tile 敷衍填洞**。
   * **側牆 Run 材質一致性 (R14)**：側牆 run 一律使用該建築 style 的專屬牆面 tile（石屋嚴禁出現木側壁，材質必須與建築風格 100% 一致）。
   * **Facade 欄位與分類隔離 (R34, R46)**：facade 僅限放置掛牆物（招牌、燈籠、遮陽篷）；麻袋、箱子等地面堆疊雜物一律歸為 props，嚴禁塞入 facade。facade 的 `cell` 欄位必須為**整數 col**，嚴禁傳入 `[col, row]` 陣列。
   * **招牌安全高度與貼牆微移 (R33)**：招牌不得撞窗撞門；掛牆前必須先取 bbox 量高，計算滿足 $h + \text{高}/23 \le \text{牆高}$（超出牆頂即畫上屋頂破圖）；招牌必須為貼牆面平行四邊形變換，鏡頭側移時與牆面完全同步微移。
   * **煙囪與遮陽篷幾何 (R32, R34)**：煙囪之 `kind` 必須宣告為 `roof`（歸屬屋頂層，非牆體）；遮陽篷功能為門廊避雨遮陽，**必須覆蓋大門（門寬 + 左右各 1 格）**，嚴禁隨意放於窗下或無門牆面。
7. **3/4 視角道具手繪標準與防鋸齒法則 (Hand-Drawn 3/4 Props & Anti-Aliasing: R0, R38, R48)**：
   * **先格後畫 (R0)**：先定義格再繪製，尺寸與著地位置嚴格對齊網格基準。
   * **手繪 3/4 Sprite 本質 (R38)**：地圖環境道具一律為一般 RPG tileset 的**手繪 3/4 視角 Sprite**；**絕非**「頂面＋正面」投影盒，亦非正俯視。**徹底廢除舊版「頂面壓扁成透視橢圓」的僵硬寫法**。
   * **參考包定位與使用鐵律**：大叔的參考包 `C:\哈維的筆記\Gaming\圖片資源\Tilesets` **只能參考視角、比例、色調，絕不直接貼進道具表**。
   * **原生像素繪製與 2× 放大法則 (R48)**：繪製時與參考圖並排放大 6× 對比，逐項對齊輪廓、色調與細節；**必須在原生像素（例 16×25）繪畫、描 1px 邊、再以 2× NEAREST 放大**。嚴禁在放大解析度直接繪製再描邊（會產生粗糙鋸齒黑塊）。

## 5. ⚠️ 這次犯過的錯：二十一大實戰血淚教訓 (Twenty-One Hard Lessons Learned in Practice)

在 v2 管線開發、chunk (0,0) 調優、閉卷考以及奴隸礦坑 V4 的實戰渲染中，團隊踩過二十一個極其深刻且具代表性的幾何地雷。這些教訓必須永久刻入工程規範，絕不再犯：

### 1. 格網行長缺失（肉眼盲信，未以程式驗證）
* **事故現場**：Markdown 高程格網手動編輯時，row 14 僅 33 字元，row 24/27/30 僅 39 字元，缺漏了字元。
* **致命後果**：少一個字元導致整行後續 col 全數左移，主河道偏移、水渠斷頭、建築基礎錯位。
* **鐵律教訓**：嚴禁憑肉眼點數！格網編輯後必須第一時間由自動化腳本執行逐行字元數 `assert len(row) == 40`，不合規直接拋出異常拒絕編譯。

### 2. 說明與資料打架（假斷崖真緩坡，文案與矩陣脫節）
* **事故現場**：設計說明宣稱「H3 斷崖面居高臨下扼守隘口」，格網矩陣底層卻填成了 `..1233333321..` 的連綿緩坡。
* **致命後果**：失去了高差立面，完全無法生成 R13/R14 的立面 run，戰術防禦機能與幾何展示徹底失效。
* **鐵律教訓**：文案與底層矩陣必須 100% 交叉核對！文字宣告斷崖處，資料矩陣相鄰格高差必須 $\ge 2$；規格與資料若有分歧，立即以資料為準或同步修正文案。

### 3. 座標轉置（[col, row] 與 [row, col] 混淆）
* **事故現場**：在組裝 Prefabs、水渠與道具時，混淆了 `(col, row)` 即 `(x, y)` 與矩陣訪問下標 `grid[row][col]` 即 `(y, x)`。
* **致命後果**：建築物被沿對角線翻轉鏡射，原本橫向的農田變成縱向，門窗朝向徹底混亂。
* **鐵律教訓**：全管線統一幾何座標為 `[col, row]`（X 向右，Y 向下）；訪問矩陣時一律封裝或明確命名為 `grid[row][col]`；並在規格組裝器中設置邊界 `assert 0 <= col < W and 0 <= row < H`。

### 4. 道具堵門（佈景未做人行通道檢驗）
* **事故現場**：為了追求「豐富的生活感」，在鐵匠鋪或民居正門口正前方放置了木箱、酒桶或石塊道具。
* **致命後果**：角色在邏輯上無法進出大門，且在 3/4 視角下道具遮擋了 2 格高的門立面與進店門檻，造成視覺與戰術邏輯雙重阻礙。
* **鐵律教訓**：建築門前 2 格被定義為「絕對通行廊道」，規格組裝器必須做碰撞檢測，嚴禁在出入口正前方佈置不可穿越的實體道具。

### 5. mask 第四頂點少 +vy（梯形投影數學缺漏）
* **事故現場**：在平行四邊形/遮罩（mask）的頂點計算時，前三個頂點都正確加上了高度投影位移 `vy = round(h * tile_h * 0.72)`，但第四個頂點漏加了 `+ vy`。
* **致命後果**：導致頂部多邊形變成傾斜撕裂的奇異梯形，渲染時出現大片扭曲拉伸，邊界產生巨大接縫。
* **鐵律教訓**：多邊形幾何投影必須使用數學結構體或統一頂點變換函數，統一計算四頂點 `(x + vx, y + vy)`，絕不手工散落編寫頂點座標公式。

### 6. 說修了沒驗證的 1 px（欺騙性修復與肉眼盲點）
* **事故現場**：口頭回報「接縫已修復完畢」，但未實際執行像素掃描，渲染圖在特定高差邊界處仍殘留 1 像素的畫布背景底色裂紋。
* **致命後果**：看似修好了，放大 800% 依然漏底破洞；這是不誠實且不負責任的交付行為。
* **鐵律教訓**：**「沒跑驗證腳本 = 沒修！」** 宣告修復前必須執行全圖背景色遍歷掃描，只有在程式印出「0 background pixel leaks detected」的客觀鐵證時，才准回報交付！

### 7. 水面層搞錯（水體高程混亂與階梯假水面）
* **事故現場**：誤將水面畫在河床高度（例如 H-1 或 H-2），或讓水流隨不同河床下沉產生多個高度斷層的水面。
* **致命後果**：水面幾何破碎撕裂，無法形成整體蓄水池，且與相鄰岸邊產生不合理的浮空或立面穿透。
* **鐵律教訓**：**一個水體只有一個水面；水面高度＝這個水體四周岸格的最低高度；四周不得有低於水面的格；河床必須低於水面。**（若本圖岸全為 H0 則水面剛好是 0，畫在 0−0.15；若水池在 H2 台地且四周岸皆 H2 則水面為 2；若一格岸為 H1 則水面只能是 1）。水體半透明蓋在河床上方，深淺完全且唯一由河床決定。

### 8. facade cell 給陣列（欄位型別失控）
* **事故現場**：在建築 facade 掛件列表中，將 `cell` 定義為 `[col, row]` 座標陣列，而非單純的整數 `col`。
* **致命後果**：渲染管線在解析立面掛件橫向位置時型別不符或計算出 NaN，導致掛件失蹤、位置錯亂或程式崩潰。
* **鐵律教訓**：facade 依附於特定牆面段，其水平位置 `cell` 必須嚴格為**整數 col**（表示牆段中的第幾格），絕對不要傳入 `[col, row]` 陣列。

### 9. 麻袋放 facade（地景道具與立面掛件混淆）
* **事故現場**：將擺在牆角的麻袋、木箱等雜物誤塞入建築外觀立面掛件（facade）列表中。
* **致命後果**：麻袋被立面管線投影為垂直掛在牆上的物件，凌空懸掛在牆體上，失去了地面接觸陰影與 Y-sort 地面遮擋。
* **鐵律教訓**：**facade 只放掛牆物（招牌、燈籠、遮陽篷）**；任何放置於地面的箱子、麻袋、木桶一律為 props，歸地面道具層渲染。

### 10. 招牌畫上屋頂（未經幾何量高直接盲貼）
* **事故現場**：未計算招牌高度與牆高上限，將招牌掛在靠近牆頂位置，導致招牌頂部超出立面牆體。
* **致命後果**：招牌直接插進屋簷與屋頂甲板，在 3/4 視角下切入屋面破圖，破壞建築幾何體的完整性。
* **鐵律教訓**：招牌不得撞窗撞門；掛牆前必須先以 bbox 量高，計算嚴格滿足 $h + \text{高}/23 \le \text{牆高}$；且招牌必須為貼牆面平行四邊形變換，鏡頭移動時與牆面完全同步微移。

### 11. 煙囪放牆上（屋頂構造誤歸立面）
* **事故現場**：把壁爐排煙的煙囪歸類在 wall / facade 立面組件中，隨立面一起平移與渲染。
* **致命後果**：剖面切至室內時煙囪浮在半空，切至屋頂時煙囪卻被屋面蓋住或錯位穿模。
* **鐵律教訓**：煙囪屬於屋面結構，其 `kind` 必須宣告為 `roof`（歸屬屋頂層，非牆體），隨屋頂層共同控制顯隱與頂層投影。

### 12. 遮陽篷放窗下（立面飾物邏輯倒置）
* **事故現場**：將遮陽篷錯誤掛在二樓窗戶下方或與窗戶重疊，未與出入口大門對齊。
* **致命後果**：視覺上如同遮擋下層窗戶的怪異踏板，破壞了建築立面的機能美學與合理採光動線。
* **鐵律教訓**：遮陽篷功能為門廊避雨遮陽，其位置**必須覆蓋大門（門寬 + 左右各 1 格）**，絕不可隨意放於窗下或無門牆面。

### 13. 石屋木側壁（建築風格材質撕裂）
* **事故現場**：在生成石砌建築的側壁 run 時，誤套用了預設或木屋風格的木質立面 tile。
* **致命後果**：建築正面是厚重石牆、側面卻露出木板紋理，材質不合邏輯，風格混亂割裂。
* **鐵律教訓**：**側牆 run 必須一律使用該建築 style 的牆 tile**（石屋不能有木側壁），嚴格杜絕風格材質撕裂。

### 14. mudflat 沉格（未貼底地硬挖低窪坑洞）
* **事故現場**：欲呈現水邊泥灘效果，卻將泥灘格子的高程下調為 H-1 或負高度，形成低於水岸的乾枯深坑。
* **致命後果**：水體周邊露出無水覆蓋的畸形斷崖落差，地形殘破且產生畸形立面接縫。
* **鐵律教訓**：岸高度必須統一在 H0！水體旁嚴禁出現「低於地面又不是水」的泥灘坑洞；**要泥灘就在 H0 鋪設泥地 (mud) tile**，嚴禁用下沉高程做地貌。

### 15. surfaces 漏水格（底表覆蓋不全導致幾何破洞）
* **事故現場**：在組裝表面資料 `surfaces` 時，誤以為水格有水覆蓋便跳過水格，或將水格 elevation 標註為河床負高。
* **致命後果**：剖面 cut 渲染或無水層檢驗時水下撕裂漏底，底層渲染器無法得知基準頂面，地表網格破洞。
* **鐵律教訓**：**surfaces 必須 100% 覆蓋每一個非建築網格（含水格）**；且水格在 surfaces 內的 elevation 必須宣告為 0（基準地面，絕非河床負高），河床高程由水體幾何與床面資料獨立管理。

### 16. 閉卷考水面倒置、建築縮小、招牌撞窗與憑空發明規則 (Round 16 Closed-Book Exam Blunders & Inventing Phantom Rules)
* **事故現場**：在第十六輪閉卷考試中，修復 12×12 地圖 spec 時接連犯下四項根本性錯誤：
  1. 誤將水面訂在 H-1、水格 surface elevation 設為 -1、河床全挖至 -2，重蹈覆轍舊版「水面低於岸」的凹陷旱坑模型；
  2. 發現雙跑樓梯建築尺寸僅 6×4 違背 R25 後，非但未依規範放大至 $\ge 8\times 6$，反而鴕鳥心態縮小成 5×4，並捏造「chunk 邊界要留通道」的假規則；
  3. 未理解南牆窗戶標準列表格式 `"0": [1, 4]`，擅自判為格式錯誤，並將兩面招牌掛在 col 1 與 col 4，直接將招牌釘死在窗戶採光面上；
  4. 遇到知識盲區或未敲定細節時頻繁腦補，憑空編造「MUD 不是合法 surface kind」、「awning kind 應為 awning」、「招牌掛 h 0.9 違反人體工學」等幽靈規則。
* **致命後果**：閉卷考 14/18 不及格且掛掉最核心項目；水體邊界裸露乾土斷崖；建築室內空間被壓縮至連樓梯踏步與通行通道都無法容納；招牌與窗戶穿模嚴重破壞立面美學與建築機能；更嚴重的是以捏造規則掩蓋認知不足，徹底背離客觀事實與工程誠信！
* **鐵律教訓**：
  1. **水面唯一與岸高約束律 (R44)**：一個水體只有一個水面，**水面高度＝四周岸格最低高度，四周不得有低於水面的格，河床必須低於水面**（若本圖岸全是 H0 則水面剛好是 0，水格 surface `elevation = wb["level"]`）；河床深淺由 `elevation_rows` 決定；泥灘亦在岸高鋪設 MUD surface，嚴禁製造低於水面的無水乾坑！
  2. **建築尺度幾何約束律 (R25)**：有樓梯之雙層建築室內必須容納踏步、井深與人行廊道，腳印**嚴格 $\ge 8\times 6$**，寧可全局移動選址放大、絕不可削足適履縮小！
  3. **立面掛件避讓避障律 (R32, R33)**：南牆窗戶清單與大門為神聖避讓區，招牌**嚴禁掛在任何門列與窗列**；掛牆物之 `kind` 統一為 `wall`（僅煙囪屋頂構造為 `roof`）；只要符合 $h + \text{高}/23 \le \text{牆高}$ 且避開門窗即合規。
  4. **嚴禁憑空捏造規則 (Zero Phantom Rule Toleration)**：閉卷考遇到不確定必須坦白標註「未知/待確認」，**絕對禁止發明不存在的規則**！一切設計必須依據空間幾何物理真實、引擎規範與客觀代碼驗證！

### 17. 同一個坑第二次掉：第二個水體（局部個案修補與未落實 Foreach 遍歷）
* **事故現場**：在第十七輪補考中，改了第一個水體（池塘）使其符合規則，但看到第二個水體（小溪原 spec 為 `level: -1`）時，直覺以為把河床挖深到 -2 即可，未將「水面＝四周岸格最低高度」升級為全域約束，在同一個同類物件上二次破戒；同時泥灘未做逐格覆蓋比對留存 -1 沉格、窗戶列表 `[1, 6]` 又被直覺擅自包裝為 `[[1, 5], [6, 5]]` 幽靈格式。
* **致命後果**：同一個坑第二次掉進去，補考僅 12/20 分；暴露了「就事論事、只修第一個、忽視陣列後續實例」的局部思維病灶，以及當客觀 schema 與個人直覺衝突時直覺壓過規則的惡習。
* **鐵律教訓**：
  1. **同類物件「Foreach 全量點名」機械動作**：凡遇陣列或多實例物件（`water_bodies`, `surfaces`, `buildings`, `props`），**絕對禁止只改第一個**！必須在檢查碼或紙面落實全量 foreach 迭代，對每個實例做不變量斷言：
     ```python
     for wb in spec["water_bodies"]:
         banks = [elev[nr][nc] for c, r in wb["cells"] for nc, nr in 四鄰(c, r) if (nc, nr) not in water]   # chunk 外算 0
         assert wb["level"] == min(banks), "水面＝四周岸格最低高度"
         assert all(elev[r][c] < wb["level"] for c, r in wb["cells"]), "河床要低於水面"
     ```
  2. **地貌高程回歸岸高機械掃描**：泥灘在岸高鋪 MUD tile，嚴禁沉格（`assert elev[r][c] == 0`）。
  3. **語法白名單比對封殺幽靈規則**：南牆窗戶格式為 `{"0": [col1, col2, ...]}`，嚴禁擅改 `[col, row]`；改完 spec 後必須跑閱卷/驗證腳本確認全 PASS 方可宣告完成。

### 18. 渲染幾何錯位雙重盲點：向量方向搞反與多格道具單格錨點 (Vector Inversion & Multi-Tile Footprint Anchoring Flaws)
在奴隸礦坑 V4 渲染器開發中，接連出現兩起典型的幾何座標 bug，導致「窗錯位、塔錯位」，且在自動化測試全通與粗略肉眼自評下完全漏看：

#### (1) 向量方向搞反：站在牆腳還往下加（窗戶畫到地面上）
* **事故現場**：在繪製南立面窗戶時，立面垂直向量 `vec_v = p_bot_l - p_top_l`（方向由牆頂指向牆腳，向下為正）。但窗戶底端座標卻寫成了 `p_win_bot = (p_bot_l[0] + vec_v[0] * 0.4, p_bot_l[1] + vec_v[1] * 0.4)`。
* **致命後果**：`p_bot_l` 本身已經站在牆腳地面上，再加上 `+ vec_v * 0.4`，等於從牆腳「再向下掉」40% 牆高，將窗戶硬生生釘死在牆體外面的泥地地表上，完全脫離牆面！而門是用 `(0, -46 * 0.72)` 向上長所以正確，造成同面牆上「門在牆上、窗在地上」的荒謬割裂。
* **鐵律教訓**：
  - **向量起點與方向嚴格對齊**：若以牆腳 `p_bot_l` 為基準向上抬升，必須**減去**向下向量：`p_win_bot = p_bot_l - vec_v * 0.4`；或等價地從牆頂 `p_top_l` 向下計算：`p_win_bot = p_top_l + vec_v * 0.6`。
  - **同牆組件高度帶互檢**：同一面牆上的門與窗，其垂直區間必須具備幾何包裹約束（$H_{\text{base}} \le Y_{\text{win\_bot}} < Y_{\text{win\_top}} \le H_{\text{wall\_top}}$），嚴禁任何組件低於牆腳或超出牆頂。

#### (2) 多格道具用單格錨點：塔往西北偏一格（物體懸空落崖）
* **事故現場**：在渲染地圖道具（props）時，寫死了單格錨點邏輯：`wy = (r + 1) * CELL`，`px = ox_base + p_base[0] + CELL / 2 - img.width / 2`，永遠只算 1 格深、1 格寬居中。
* **致命後果**：當道具佔地為多格時（如西北角 3×3 巨型哨塔 `watchtower_nw`、3×2 奴隸主帳篷、2×2 雙熔爐與水井），哨塔佔 `[3, 1]` 到 `[5, 3]`，按 1×1 計算等於將整座塔往西偏了一格半、往北偏了兩格，導致塔腳完全脫離 H3 台地邊緣，硬生生懸空在懸崖外側的低地上！
* **鐵律教訓**：
  - **讀取完整 Footprint 動態計算腳底與置中**：
    ```python
    fw, fh = p.get("footprint", [1, 1])
    wx = c * CELL
    wy = (r + fh) * CELL                                      # 腳底接觸線＝footprint 最南緣
    p_base = PV(wx, wy, h, cam_x)
    px = int(ox_base + p_base[0] + fw * CELL / 2 - img.width / 2)   # 橫向跨 fw 格置中
    py = int(oy_base + p_base[1] - img.height)
    ```
  - **Y-Sort 深度鍵必須以最南緣為準**：`depth_key = ((pr + fh) * CELL) - (pe * 10)`，確保多格大型物件的遮擋層級正確覆蓋北側相鄰物體。

### 19. 剖面高度除零與 Canvas `IndexSizeError` 致命黑屏
* **事故現場**：鍛造坊挑高至 4.0，而立面繪製高度寫死為 69px。當切到 H1 剖面時，截斷立面的切片高剛好為 $69 - 69 = 0\text{px}$。原生 Canvas 的 `ctx.drawImage` 傳入寬高 $\le 0$ 會直接拋出 `IndexSizeError` 致命例外，中斷整個 Canvas 渲染迴圈，導致剖面下方整片全黑。
* **鐵律教訓**：所有 Canvas 切片與投影渲染函式（`drawPara`、`wallBand`、`band`、`sideBand`）入口必須裝配嚴格的 `if (!img || sw <= 0 || sh <= 0) return;` 與 `if (y1 <= y0) return;` 看門狗，並依建物實際 `floorH` 動態計算立面畫布高度，嚴禁寫死固定像素。

### 20. 雙端投影錨點分叉（Python 離線合成 vs JS 檢視器漂移）
* **事故現場**：Python 端靜態渲染係以道具佔地「底邊中心點」投影，而 JS 檢視器一度使用「左上頂點」投影再疊加偏移，導致只要道具具備高程 (elevation) 或多格佔地，兩端視覺位置即嚴重撕裂。
* **鐵律教訓**：雙端幾何投影公式必須 100% 同源同構！統一採用「底邊中心接地投影點」：
  $$\text{Anchor} = \text{PV}\left(\left(c + \frac{w}{2}\right) \times \text{CELL}, (r + h) \times \text{CELL}, \text{elevation}\right)$$
  螢幕渲染座標統一為 `screen_x = Math.round(pt.x - (sw / 2) * sc)`、`screen_y = Math.round(pt.y - sh * sc)`。

### 21. 高架懸空建築基座台地邊緣踩空（哨塔四腳落崖）
* **事故現場**：在放置 4 柱高架哨塔等佔地 $4\times 4$ 的大型預製體時，高台邊界緊貼塔基，導致西南側兩支腳柱直接懸空踩在斷崖懸崖外側低地上。
* **鐵律教訓**：高架建築外圍必須由規格組裝器強制約束留出至少 $2\sim 3$ 格平整石台岩盤緩衝帶（同一高程），確保四隻支撐立柱 100% 踩踏於實體地面上。
